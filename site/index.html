services-ops-intelligence

Predictive support and parts forecasting for an installed base of hardware, built the way a Services Operations team would use it.

Repository on GitHub README reports/ (the source of every number here) docs/memo.md
Realthe drive telemetry (Backblaze Hard Drive Data, 2026 Q2: 31.97 million drive-days, 359,101 drives, 1,522 failures), the failure labels, the failure model and every dispatch-budget number.
Generatedthe enterprise around it (accounts, sites, cases, dispatches, parts, runbooks) from a seeded generator with ground truth, so the parts, repeat-dispatch and deflection numbers test the method, not any real operation.
What is live here. This page is static: scripts/build_site.py reads reports/ and docs/memo.md and writes the JSON the charts draw from. The Streamlit dashboard and Postgres do not run on Vercel. Run the dashboard locally with make dashboard from a clone (it reads reports/ only, no data download needed).

Repeat dispatches (generated support tables)

Repeat rate and avoidable-repeat rate by case category

reports/repeat_dispatch.csv, dimension = case_category

A repeat is visit 2 or 3 on the same case, or a first visit within 30 days of a previous dispatched case closing on the same asset. The rates reproduce the generator's rules; they are not a finding about any real operation.
